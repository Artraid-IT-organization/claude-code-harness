# Vault — рабочее хранилище

Единая плоскость задач, решений и знаний рабочего контура. Обычный каталог с Markdown-файлами:
открывается Obsidian, редактируется чем угодно, синхронизируется через git.

**Источник правды** — сервер. Локальные клоны на ноутбуке и телефоне синхронизируются с ним,
а не наоборот.

## Зачем это ассистенту

Он читает отсюда контекст задачи и пишет сюда результат. Разговор в чате исчезает вместе с сессией,
файл в vault — остаётся. Правило простое: то, что должно пережить сессию, лежит здесь, а не
в переписке.

## Структура

```
vault/
├── principles/    # Принципы принятия решений и Decision Loop — читается каждую сессию
├── knowledge/     # Методики и заметки: как мы что-то делаем
├── projects/      # Долгоживущие инициативы, один файл = один проект
├── tasks/         # Отдельные задачи и брифы исполнителям
├── decisions/     # ADR: принятые решения с контекстом и последствиями
├── daily/         # Дневные заметки
├── weekly/        # Недельные разборы
├── analysis/      # Разовая аналитика, выгрузки, расчёты
└── inbox/         # Быстрые захваты, разбираются при недельном разборе
```

## Что здесь НЕ живёт

- Секреты: токены, ключи, пароли. Им место в `~/.secrets/` или менеджере паролей, и никогда в git
- Личное, если vault рабочий
- Большие бинарные файлы: репозиторий станет неподъёмным, а история — бесполезной

## Конвенции

- Имя файла задачи: `ГГГГ-ММ-ДД-краткое-описание.md`
- В каждом долгоживущем документе — дата актуальности сверху. Документ без даты через месяц
  неотличим от протухшего
- ADR не редактируются задним числом: решение изменилось — пишется новый, старый помечается
  как замещённый
