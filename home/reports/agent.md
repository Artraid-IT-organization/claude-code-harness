# agent.md — reports

Проект отчётов для руководства. Вход в тему: `README.md` → `METHOD.md` (как писать) →
`SOURCES.md` (откуда факты). Скилл-обёртка: `~/.claude/skills/report/SKILL.md`.

## Устройство

`archive/` — пары `.md` (исходник, источник правды) и `.docx` (то, что ушло).
`tools/` — генератор в обе стороны, сбор фактуры, отправка. `templates/base.docx` — каркас оформления.

## Неочевидное

- **На сервере нет ни pandoc, ни python-docx, ни unzip.** Поэтому `md2docx.py` собирает документ
  прямой генерацией WordprocessingML внутрь копии `templates/base.docx`, а распаковка идёт
  через `zipfile` из стандартной библиотеки. Не пытаться поставить python-docx — ломать рабочую схему незачем.
- **Каркас важнее разметки.** Из `base.docx` берутся стили, шрифты, нумерация списков и колонтитул;
  заменяется только `word/document.xml`. Отсюда единый вид всех отчётов и календарей CEO.
  Замена `base.docx` меняет вид всего архива при пересборке.
- **Ширины колонок считаются автоматически** по длине содержимого, сумма всегда 9638 twips —
  ширина полосы набора A4 с полями 2 см. Руками ширины не задавать.
- **Round-trip проверен и обязателен как приёмка:** `docx2md(md2docx(x)) == x`. Любая правка
  генератора проверяется этим сравнением, иначе тихо поедет структура таблиц.
- **Кириллица в docx** ломается молча при неверной кодировке. Готовый файл всегда вычитывать
  через `docx2md.py файл -` перед отправкой.
- `collect_facts.sh` отсекает `[doc-patrol]` — это сторож документации, а не работа человека.
  Его количество печатается отдельно, чтобы объём не выглядел завышенным.
- Токен Telegram и получатель — в `~/.env` (`TG_BOT_TOKEN`, `TG_CHAT_ID`). В коде их нет: `send_tg.py` без них останавливается с понятной ошибкой.
  В git не коммитить ни то, ни другое.

## DoD правки здесь

Правишь генератор — прогони round-trip на всех файлах `archive/*.docx` и сверь результат.
Меняешь правила стиля — обнови `METHOD.md` и продублируй ключевое в скилл, иначе сессия
без этого проекта в контексте соберёт отчёт по-старому.
