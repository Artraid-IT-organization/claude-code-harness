# reports — отчёты о работе для руководства

Хранилище отчётов владельца (CDTO) и всё, что нужно, чтобы собрать новый:
методика, карта источников фактуры, генератор документов, архив отправленного.

Проект самодостаточен: любая сессия Claude Code из любого каталога может собрать
отчёт, прочитав `METHOD.md` и `SOURCES.md`, без контекста прошлых переписок.

## Быстрый путь

```bash
cd ~/reports

# 1. фактура за период (конец не включается)
tools/collect_facts.sh 2026-07-13 2026-07-20

# 2. написать archive/2026-07-20-nedelya-13-19.07.md по структуре из METHOD.md

# 3. собрать документ
python3 tools/md2docx.py archive/2026-07-20-nedelya-13-19.07.md \
                         archive/2026-07-20-nedelya-13-19.07.docx

# 4. вычитать глазами получателя
python3 tools/docx2md.py archive/2026-07-20-nedelya-13-19.07.docx -

# 5. отправить в Telegram
python3 tools/send_tg.py archive/2026-07-20-nedelya-13-19.07.docx "Итоги недели 13-19.07"

# 6. закоммитить
git add -A && git commit -m "отчёт: неделя 13-19.07"
```

Или просто попросить Claude Code: сделай недельный отчёт — сработает скилл `report`.

## Что где

| Файл | Назначение |
|---|---|
| `METHOD.md` | Как писать: правило единицы отчёта, стиль, структура недельного и дневного, порядок сборки, проверка фактов |
| `SOURCES.md` | Где брать факты: проекты, снапшоты состояния, штабные файлы, что не считать работой |
| `archive/` | Отправленные отчёты: `.md` — исходник, `.docx` — то, что ушло руководству |
| `templates/base.docx` | Каркас оформления: стили, шрифты, нумерация, колонтитул. Взят из календаря разработки CRM |
| `templates/weekly.md`, `daily.md` | Скелеты под заполнение |
| `tools/md2docx.py` | Markdown → docx. Прямая генерация WordprocessingML: на сервере нет pandoc и python-docx |
| `tools/docx2md.py` | docx → Markdown. Вычитка своих документов и чтение входящих от CEO |
| `tools/collect_facts.sh` | Сбор фактуры за период по всем проектам сервера |
| `tools/send_tg.py` | Отправка в Telegram CEO |

## Правила проекта

- Исходник отчёта — `.md`, он источник правды. `.docx` собирается из него и не правится руками.
- Имя файла: `ГГГГ-ММ-ДД-тип.md`, где дата — день отправки. Тип: `den`, `nedelya-ДД-ДД.MM`.
- Отправленный отчёт не переписывается. Правки — новым файлом.
- Числа в отчёте подтверждены доком или гейтом, а не формулировкой коммита.
