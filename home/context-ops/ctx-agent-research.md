## 1. Платформенные факты Claude Code (проверено через claude-code-guide, 19.07.2026)

- **Окно**: 200k стандартные модели; **1M** — Fable 5 / Sonnet 5 / Opus 4.6+ (code.claude.com/docs/en/context-window.md).
- **Auto-compact**: срабатывает у лимита, порог НЕ документирован и НЕ настраивается; сжатие истории до **~12% объёма**; microcompact НЕ существует.
- **/compact [instructions]**: принимает инструкции суммаризации. После компакта: system prompt/CLAUDE.md/MEMORY.md/скиллы переинжектятся; **path-scoped правила и вложенные CLAUDE.md теряются** до повторного чтения файлов.
- **/clear и /compact программно НЕДОСТУПНЫ**: только ручные команды; хуки не могут их вызвать (code.claude.com/docs/en/sessions.md).
- **Хуки**: PreCompact — вход {source: manual|auto}, может БЛОКИРОВАТЬ (decision:block); SessionStart — matcher startup|clear|compact, stdout → инжект в контекст (наша автоматика: afm-checkpoint-inject.sh, afm-precompact-guard.sh — внедрены 19.07).
- **Headless**: `claude -p --model X --output-format json`, `--resume <session-id>`, `--bare` (без хуков/CLAUDE.md/MCP). `--model` при resume всегда важнее сохранённой. Паттерн «волна = свежая сессия» = кандидат CTX-2.
- **Кэш Anthropic**: cache read = **0.1×** base input; cache write = 1.25×; TTL 5 мин (в наших сессиях — 1ч), сброс TTL каждым чтением; **/compact меняет префикс → cache miss + rebuild** (platform.claude.com).
- Явных встроенных предупреждений о заполнении нет; аудит — команда `/context`.

## 2. Наука о деградации длинного контекста

- **Chroma «Context Rot»** (trychroma.com/research/context-rot): 18 фронтир-моделей; деградация качества начинается ЗАДОЛГО до лимита окна, заметная уже с ~25% номинала (напр. ~50k при 200k).
- **NoLiMa** (LMU/Adobe, ICML 2025): retrieval без лексического совпадения — у 11 из 12 моделей точность <50% уже при 32k.
- **«Lost in the Middle»** (2023): информация из середины длинного контекста теряется; края помнятся лучше.
- **MECW (Paulsen 2025)**: «максимальное эффективное окно» кратно меньше заявленного (в отдельных случаях на 99%).
- Для кодинг/агентских сессий context rot называют первичным режимом отказа: шум поиска/бэктрекинга деградирует все последующие ответы.

## 3. Выведенные правила (CTX v2, канон AFM)

- **Сброс (clear) на КАЖДОЙ границе волны**: экономический break-even ≈50k контекста при ≥15 ходах следующей волны (налог = N×0.1/ход против 60–100k восстановления из файлов); качественная зона риска начинается кратно раньше номинала. Порог «300k» не обоснован — отброшен.
- **Автоматика**: SessionStart-хук сам инжектит CHECKPOINT.md активной AFM-программы (после /clear вводная не нужна); PreCompact-хук блокирует авто-компакт при WAVE_ACTIVE. Предел платформы: нажатие /clear — за человеком.
- **/compact** — аварийный mid-wave инструмент (лоссивый, ~12%), только с инструкциями + восстановительный чек.
- **Восстановительный чек** (5 вопросов из файлов) — измеряет деградацию после clear/compact; промах = дефект CHECKPOINT, чинится файл.
- **CTX-1**: замер расхода волна-до/волна-после + чек → факты в канон. **CTX-2**: headless-раннер волн — после CTX-1.
