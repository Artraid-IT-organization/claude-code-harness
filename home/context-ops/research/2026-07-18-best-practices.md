# Свод мировых практик: экономия контекста и лимитов Claude Code

> Ресёрч выполнен 18.07.2026 (веб + официальные доки). Повторять не нужно — при апдейте дописывать сюда.

## 1. Фикс-налог старта сессии

- **CLAUDE.md — самый дорогой файл**: грузится каждую сессию и висит в каждом сообщении.
  Официальная рекомендация — коротко (<~200 строк), тест каждой строки: «уберу — Claude начнёт
  ошибаться?» Если нет — удалить. Раздутый CLAUDE.md вреден вдвойне: жжёт токены И правила
  теряются в шуме. Бенчмарк сообщества: 3 847 → 312 токенов без потери качества.
- **Доменные знания — в скиллы, не в CLAUDE.md**: скиллы подгружаются по требованию,
  CLAUDE.md — всегда. Но: короткие ОПИСАНИЯ всех скиллов грузятся в каждую сессию,
  поэтому число установленных скиллов — тоже статья налога.
- **Импорты `@файл` = часть налога**: каждый импортированный файл платится каждую сессию.
  Проверка того, что реально загружено: `/context`.

## 2. Живой контекст сессии

- **`/clear` между несвязанными задачами** — антипаттерн №1 по официальному гайду —
  «kitchen-sink session». Чистая сессия с хорошим промптом почти всегда бьёт длинную
  сессию с накопленными поправками.
- **`/compact` вручную на ~40–50%**, с инструкцией (`/compact сфокусируйся на API-изменениях`).
  Поведение компактации можно закрепить в CLAUDE.md («сохранять список изменённых файлов»).
- **Субагенты на исследование**: читают файлы в своём контексте, возвращают вывод.
  Пример Anthropic: субагент прочитал 6 100 токенов файлов, вернул 420.
- **`/btw`** для побочных вопросов — ответ не попадает в историю.
- **Две неудачные поправки → `/clear`** и новый промпт: контекст уже отравлен неудачными
  попытками.
- **Spec → чистая сессия**: интервью/спека в одной сессии, исполнение — в новой чистой.
- **Длинный контекст жжёт лимит быстрее** (официальный help-центр): «длинные разговоры,
  задействующие автоматическое управление контекстом, расходуют больше лимита; при подходе
  к лимиту начинайте новый разговор».

## 3. Инструменты, MCP, скиллы

- **MCP-схемы стоят до десятков тысяч токенов** (замеры сообщества: 18k токенов на ход,
  до 66k+ на старте при множестве серверов). Правило: подключать только нужные серверы,
  и только в тех проектах, где они используются.
- Tool Search в Claude Code авто-включается, когда MCP-схемы превысили бы ~10% окна, —
  но лучше не доводить: неиспользуемый сервер = удалить из конфига.
- **CLI-утилиты дешевле MCP**: `gh`, `aws`, кастомные скрипты — самый контексто-эффективный
  способ работать с внешними сервисами (официальная рекомендация).
- Официальный help-центр: «инструменты и коннекторы токеноёмки — отключение лишних
  максимизирует окно и оптимизирует лимиты».

## 4. Подписка и лимиты

- Лимит — общий бакет на Claude Code + claude.ai + Cowork; 5-часовое окно + недельная планка.
- Расход зависит от: модели, длины контекста, extended thinking, числа tool-вызовов и ретраев.
- **Окно 1M**: ценовой премиум на API снят в марте 2026 (раньше >200k input = 2×), но для
  подписки суть не меняется: гигантский контекст в каждом сообщении = кратный расход лимита.
  1M включать точечно, не держать дефолтом.
- Мониторинг: `/usage` (проекция burn-rate), статус-лайн с % контекста, `/context` (что загружено).

## 5. Автоматика (headless, `claude -p`)

- Каждый запуск платит полный фикс-налог каталога (CLAUDE.md-цепочка + скиллы + память) —
  кэш между отдельными процессами не переиспользуется. Частые мелкие вызовы — самая дорогая
  форма использования подписки.
- Рычаги: явный `--model` по сложности задачи (классификация = haiku-уровень — наша же
  доктрина cost-curve), батчинг мелких задач в один вызов, `--allowedTools` для скоупа,
  тонкий CLAUDE.md в каталоге бота.
- Fan-out по файлам — норм. паттерн, но модель и промпт калибровать на 2–3 файлах до масштаба.

## 6. Прочее

- **Кириллица дороже**: ~1.5–2 токена там, где латиница берёт 1. Часто загружаемые
  операционные файлы (CLAUDE.md, индексы) выигрывают от плотного стиля и коротких хуков.
- Verification-first (тест/скрипт/скриншот как критерий) сокращает ретраи — ретраи тоже лимит.
- Plan mode полезен при неопределённости, но для маленьких правок — оверхед: «если diff
  описывается одним предложением — без плана».
