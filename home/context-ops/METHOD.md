# Методика Context Ops

> Актуально: 18.07.2026. Источники и обоснование цифр: `research/2026-07-18-best-practices.md`.

## Модель расхода: три статьи

Каждый запрос к Claude оплачивается всем контекстом, который модель держит в этот момент.
Расход подписки складывается из трёх статей:

- **А. Фикс-налог старта** — грузится в КАЖДУЮ сессию до первого слова: цепочка CLAUDE.md
  с импортами, индекс памяти (MEMORY.md), описания ВСЕХ установленных скиллов, схемы
  MCP-инструментов, инъекции хуков (уроки, очередь решений).
- **Б. Живой рост сессии** — прочитанные файлы, выводы команд, история. Чем длиннее сессия,
  тем дороже каждое следующее сообщение; качество при переполнении тоже падает.
- **В. Автоматика × частота** — боты и кроны платят статью А при каждом запуске.
  Множитель: запусков/день × размер контекста × «цена» модели.

Аксиома приоритета: **сначала В (множитель), потом А (налог), потом Б (дисциплина)**.
Одна строка `--model` в боте с 40 запусками/день даёт больше, чем неделя чистки доков.

## Нормативы (бюджеты)

| Метрика | Норматив | Почему |
|---|---|---|
| Цепочка CLAUDE.md + импорты (штаб, `~`) | ≤ 16 КБ | Официально: CLAUDE.md < 200 строк; раздутый файл — правила теряются |
| MEMORY.md (индекс памяти) | ≤ 10 КБ | Индекс = title + короткий хук; детали живут в topic-файлах |
| Скиллов установлено | ≤ 30 | Описания всех скиллов грузятся в каждую сессию, включая ботов |
| Модель по умолчанию в settings.json | без `[1m]` | Окно 1M провоцирует сверхдлинные сессии; длинный контекст жжёт лимит быстрее |
| Модель каждого бот-вызова | явный `--model` по cost-curve | Классификация/извлечение JSON = haiku-уровень, не дефолт штаба |
| Фикс-налог каталога автоматики | ≤ 10 КБ | Бот не должен наследовать тяжёлую обвязку |
| Сессия | = 1 задача | Kitchen-sink-сессия — главный антипаттерн по официальному гайду |

## Петля аудита (еженедельно или при жалобе на лимит)

1. **Замер** — `~/context-ops/bin/ctx-audit.sh` (пишет raw-отчёт в `audits/`).
2. **Диагноз** — сравнить с нормативами; нарушения = кандидаты в план.
3. **Рычаги** — взять из таблицы ниже, сверху вниз (по убыванию эффекта).
4. **Применить** — конфиг/файлы/скрипты; деструктивное — через ок владельца.
5. **Контроль** — через неделю `/usage` + повторный замер; дельту записать в `audits/`.

## Рычаги (по убыванию эффекта)

| # | Рычаг | Как |
|---|---|---|
| 1 | Модель автоматики по cost-curve | Каждому `claude --print` — явный `--model`; классификаторы → haiku; сложный анализ → sonnet; Fable — только там, где реально нужен. Данные: sonnet на чистом AFM-узле = −69% токенов без потери качества (замер 18.07) |
| 1а | Ретрай-бюджет ≤2 | Цену прогона делают ретраи, не тир модели (замер AFM 18.07: 3 ретрая по битой фикстуре = 1.2М токенов). Второй провал = стоп + диагностика харнесса; фикстуры/селфтесты получают дешёвый смоук ДО запуска дорогого узла |
| 1б | Внешний контур Codex | Независимое ревью / tier-B верификация / бойлерплейт → `bin/codex-agent.sh` (бюджет OpenAI, не лимит Claude); деградация железная: CODEX_UNAVAILABLE → sonnet-субагент + пометка в отчёте |
| 2 | Убрать `[1m]` из дефолтной модели | `settings.json`; 1M включать точечно на задачу, где правда нужен весь корпус |
| 3 | Диета фикс-налога | Импорты CLAUDE.md — только то, без чего сессия ошибётся; остальное «по запросу»; MEMORY.md — сжать хуки; скиллы — вычистить пакеты |
| 4 | Дисциплина сессий | Правила ниже; главный эффект — не платить за мёртвый контекст |
| 5 | Субагенты на ресёрч | Изучение кода/файлов → субагент, в главный контекст возвращается вывод, а не файлы (пример Anthropic: 6100 токенов файлов → 420 токенов ответа) |
| 6 | MCP-гигиена | Неиспользуемые серверы отключать; MCP-схемы стоят до десятков тысяч токенов; CLI-утилиты дешевле MCP |
| 7 | Язык операционных доков | Кириллица ≈ в 1.5–2 раза дороже латиницы на знак; часто загружаемые файлы писать плотно |

## Дисциплина сессий (штаб и воркеры)

- Сессия = задача. Между несвязанными задачами — `/clear`.
- `/compact` вручную на ~40–50% заполнения, не дожидаясь автокомпакта.
  В CLAUDE.md проекта — инструкция «при компактации сохранять список изменённых файлов и команды тестов».
- Ресёрч по кодовой базе → субагент; «инвестигация без скоупа» запрещена.
- Побочный вопрос → `/btw` (не попадает в историю).
- Две неудачные поправки подряд → `/clear` и новый промпт с учётом выясненного.
- Крупная вещь: spec-сессия → чистая сессия на исполнение (у нас это AFM).

## Чеклист запуска новой автоматики (бот, крон, петля)

- [ ] Модель задана явно (`--model`), выбрана по cost-curve (см. скилл `cost-curve`), не дефолт settings.
- [ ] Фикс-налог рабочего каталога ≤ 10 КБ (тонкий CLAUDE.md, без наследования тяжёлой обвязки).
- [ ] Батчинг: N мелких однотипных задач = 1 вызов, где возможно.
- [ ] `--allowedTools` ограничен до нужного.
- [ ] Ретрай-бюджет ≤2 и записан в код; второй провал = стоп + алерт, не долбить дорогую модель.
- [ ] Проверочный харнес (фикстуры, селфтесты) прогнан дешёвым смоуком ДО боевого запуска.
- [ ] Посчитан недельный бюджет: запусков/день × средний контекст × вес модели — и он согласован.

## Как запускать

Фраза в чате: **«проведи контекст-аудит»** → скилл `ctx-audit` выполняет петлю целиком.
