# Claude Code Harness

Рабочая обвязка для Claude Code: правила, хуки, память, скиллы и дисциплина, превращающие ассистента
из «умного автодополнения» в участника работы, который помнит контекст, учится на своих промахах
и не требует объяснять одно и то же каждую сессию.

Собрано в боевой эксплуатации на сервере, где Claude Code ведёт разработку, аналитику, отчётность
и автоматизацию. Это не демо и не концепт — это то, что работает каждый день.

---

## Проблема, которую это решает

Claude Code из коробки не помнит вчерашний день. Каждая сессия начинается с нуля: кто ты, чем
занимаешься, что уже решено, на какие грабли уже наступали. Обычная реакция — раздувать один
огромный файл правил, который читается каждую сессию, съедает контекст и всё равно не срабатывает
там, где нужно.

Харнесс решает это иначе:

- **Разделение по частоте использования.** Всегда читается только точка входа и три коротких файла.
  Остальное подключается по требованию.
- **Память как файлы, а не как простыня.** Индекс в контексте, детали на диске.
- **Уроки вместо повторных объяснений.** Поправил ассистента один раз — правка возвращается
  в следующих сессиях автоматически.
- **Дисциплина на уровне роли.** Правила, применяемые ДО ответа, а не вспоминаемые после.

## Что внутри

### Хуки — механика, работающая без напоминаний

| Хук | Событие | Что делает |
|---|---|---|
| `loop-recall.sh` | старт сессии | подставляет в контекст уроки прошлых сессий |
| `loop-record.sh` | конец сессии | записывает метаданные сессии для последующей дистилляции уроков |
| `decision-queue.sh` | старт сессии | показывает счётчик вопросов, ждущих решения владельца |
| `agentmd-guard.sh` | правка кода | напоминает обновить документацию подсистемы, если она устарела относительно правки |
| `afm-checkpoint-inject.sh` | старт сессии | подставляет чекпойнт активной многодневной программы работ |
| `afm-precompact-guard.sh` | авто-сжатие | блокирует сжатие контекста в середине рабочей волны — до фиксации состояния в файлы |

Важная деталь `loop-recall.sh`: он молчит в каталогах ботов и во временных каталогах. Одноразовые
вызовы `claude --print` из автоматики отдают результат живым людям — служебному контексту там не место.
Это правило появилось после того, как служебная фраза утекла в текст рассылки.

### Петля обучения

Локальная база SQLite, в которой копятся уроки: что пошло не так, какой был контекст, какой вывод.
Цикл: захват трейса → оценка → дистилляция в урок → возврат в контекст следующих сессий.
Персональные данные маскируются при записи. Уроки делятся на области — уроки одного проекта
не всплывают в другом.

```
loop.py record-trace --task-kind deploy --input "..." --output "..." --outcome fail \
                     --error-class "урок одной фразой"
loop.py evaluate      # обязательно: без этого distill не увидит трейс
loop.py distill
```

Ручная ревизия — команда `/learning-review`: предлагает кандидатов в уроки, записывает только
подтверждённые.

### Скиллы

| Скилл | Для чего |
|---|---|
| `afm` | крупная задача как граф артефактов: параллельное исполнение по готовности входов, независимая верификация на границе каждого узла |
| `worker-brief` | делегирование большой задачи в отдельную сессию: шаблон брифа, планка приёмки, красные линии, обязательный независимый аудит |
| `ctx-audit` | аудит расхода контекста: замер, диагноз, план оптимизации |
| `cost-curve` | выбор модели по цене ошибки: обычный код → дешёвая модель → старшая |
| `report` | отчёт руководству: сбор фактуры по всем проектам, генерация Word, отправка |
| `grillme` | глубокое интервью: вытащить полную картину задачи вопросами до начала работы |
| `codex-agent` | вызов внешней модели как субагента для независимого ревью |
| `iterative-product-rebuild` | методология пересборки продукта или подсистемы |

### Профили субагентов

19 готовых ролей: архитектор, критик, отладчик, ревьюер безопасности, верификатор, тест-инженер,
трассировщик причинно-следственных связей и другие. Каждый со своим системным промптом и набором
инструментов.

### Обвязка

- **`scripts/runjob.sh`** — раннер длинных пачечных процессов. Пропускает уже сделанное, докручивает
  волнами до нулевого остатка, переживает обрыв сессии. Статус берётся из файла состояния, а не
  подсчётом файлов глазами: счётчик может стоять часами и выглядеть как «идёт работа».
- **`scripts/gen_services.py`** — генератор снапшота сервера: systemd, docker, cron, порты, MCP.
  Значения токенов и паролей маскируются при сборе.
- **`context-ops/`** — методика экономии контекста с нормативами и чеклистами.
- **`reports/`** — методика отчётности: где брать факты, как считать, генератор Word, отправка.
- **`vault/`** — структура рабочего хранилища: задачи, проекты, ADR, знания, принципы.

## Установка

Требуется: Linux или macOS, Python 3.8+, Claude Code. Желательно Node.js и git.

```bash
git clone https://github.com/Artraid-IT-organization/claude-code-harness.git
cd claude-code-harness
bash install.sh      # раскладывает файлы, сливает настройки, инициализирует петлю
bash onboard.sh      # интервью: заполняет конфигурацию под тебя
```

`install.sh` **не затирает** существующую конфигурацию Claude Code: твои разрешения и предпочтения
сливаются с настройками харнесса, прежнее состояние бэкапится в `~/.harness-backup-<дата>`.

`onboard.sh` задаёт восемь вопросов о тебе и твоих проектах, после чего Claude сам заполняет
шаблоны — это работает заметно лучше ручной правки плейсхолдеров.

## Как это устроено

```
~/CLAUDE.md                     # точка входа, читается каждую сессию
~/.claude/
  ├── settings.json             # модель, уровень усилий, привязка хуков
  ├── settings.local.json       # 151 преднастроенное разрешение
  ├── hooks/                    # 7 хуков
  ├── agents/                   # 19 профилей субагентов
  ├── skills/                   # 8 скиллов
  ├── learning-loop/            # петля обучения
  ├── workspace/
  │   ├── SOUL.md               # кем ассистент работает
  │   ├── USER.md               # кто владелец
  │   ├── PROTOCOLS.md          # дисциплина: фильтр ответа, цифры, модели, линзы
  │   ├── DECISIONS.md          # очередь вопросов, ждущих решения владельца
  │   └── SERVICES.md           # снапшот сервера (генерируется)
  └── projects/-<слаг>/memory/  # долгосрочная память
~/vault/                        # задачи, проекты, решения, знания
~/context-ops/                  # методика экономии контекста
~/reports/                      # методика отчётности + инструменты
~/scripts/                      # раннер длинных процессов, генератор снапшота
```

### Самая ценная часть

`workspace/PROTOCOLS.md`. Читается каждую сессию и определяет поведение сильнее всего остального:

- **Фильтр перед ответом.** Три вопроса: на каком слое задан вопрос, чьё это решение, не сдвинулась
  ли рамка. Отвечать планом на вопрос о модели — самая частая и самая дорогая ошибка ассистента.
- **Дисциплина цифр.** Каждая публикуемая цифра — с единицей, знаменателем и методом в той же фразе.
- **Стоп-правило.** Две коррекции рамки подряд → остановиться, пересказать понимание, дождаться
  подтверждения. Не производить новые артефакты.
- **Маршрутизация моделей.** Старшая модель там, где есть выбор, риск или вердикт. Средняя — на
  массовом и механическом. Продукт средней модели — полуфабрикат, пока старшая его не приняла.

## Что НЕ входит

Осознанно не входит в поставку:

- Секреты в любом виде. `~/.env`, ключи, токены заводятся владельцем самостоятельно
- Чужая память и чужие уроки: база петли обучения стартует пустой
- Транскрипты сессий, история, кэши
- Проектные данные и рабочие репозитории
